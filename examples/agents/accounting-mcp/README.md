# Пример адаптера учётной системы (MCP)

Небольшой MCP-сервер поверх HTTP-API вымышленной учётной системы «Учёт». Показывает, как подключить к Coma систему, где центр ведёт расписание слотов, не меняя ядро. Все данные вымышленные; это образец, а не коннектор к 1С.

- `accounting-api.ts` — вымышленная учётная система: `GET /api/slots?date=`, `GET /api/instructors`, `POST /api/slots/{id}/assign`. Ключ — `Authorization: Bearer <ACCOUNTING_API_TOKEN>`.
- `server.ts` — MCP-адаптер (streamable HTTP, JSON-RPC на `POST /mcp`). Действия:
  - `get_slots` — слоты на дату (чтение);
  - `find_free_instructors` — инструкторы без слота в это время (чтение);
  - `assign_instructor` — назначить инструктора на свободный слот (изменяет данные, `readOnlyHint: false`; Coma выполнит его только после подтверждения человеком).
- `notify.ts` — отправка подписанного события во входящий вебхук Coma.
- `smoke.ts` — проверка сценария целиком по протоколу MCP.
- `slots.csv` — то же расписание таблицей для варианта «без интеграции».

Требуется Node.js 22.6 или новее, зависимостей во время выполнения нет.

```bash
npm run smoke                      # проверка: initialize, tools/list, слоты, назначение
npm start                          # учётная система на :4010, адаптер на :4020
MCP_HOST=0.0.0.0 npm start         # адаптер доступен Core из контейнера
npm install && npm run check       # проверка типов
```

Переменные: `ACCOUNTING_API_TOKEN` (по умолчанию `accounting-demo-token`), `MCP_TOKEN` (`mcp-demo-token`), `ACCOUNTING_PORT`, `MCP_PORT`, `MCP_HOST`, `ACCOUNTING_API_URL` — адрес настоящего API вместо вымышленного.

## Подключение к Coma

1. Оператор сервера вносит адрес адаптера в `INTEGRATIONS_ALLOWED_PRIVATE_TARGETS` (например `192.168.1.20:4020`) — без этого Coma не обращается к внутренним адресам.
2. «Агенты → Подключения → Интеграции → Подключить систему»: имя `accounting`, адрес `http://<хост>:4020/mcp`, заголовок `Authorization` со значением `Bearer mcp-demo-token`, отметки «Система во внутренней сети» и «Разрешить агентам»; «Изменения только с подтверждением» оставить включённым.
3. «Проверить связь» — появятся три действия, `assign_instructor` помечено «изменяет данные».
4. В конструкторе агента «Слоты» выбрать подключение и действия; для `assign_instructor` — «после подтверждения».

Событие «слот освободился» в чат агента:

```bash
COMA_WEBHOOK_URL=https://coma.example.com/api/v1/hooks/<id> \
COMA_WEBHOOK_SECRET=whsec_... npm run notify -- s-2
```

Как адаптировать под свою систему: замените вызовы `fetch` в `adapterTools()` на запросы к своему API, сохраните имена и формат ответов действий, чтобы рецепт агента не пришлось менять. Подробнее — [Как подключить учётную систему](../../../docs/integrations/accounting-system.md).
