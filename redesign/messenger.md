# Оболочка, список чатов, беседа, композер — чего не хватает

Модули `apps/web/src/shell`, `chats`, `conversation`, `composer`. Всё, что можно было собрать на текущем API, собрано; ниже — разрывы между макетом «Мессенджер» и бэкендом/продуктом.

## Оболочка и Welcome
- **Имя автора в in-app уведомлении** («Мария Лебедева · Дизайн-команда»): в событии `message.created` нет `actor_display_name`, только `actor_id`. Показываем название чата. Нужно `actor_display_name` в payload события (как в `MessagePreview`).
- **Карточка «согласований агента»** строится по `GET /agents/tool-confirmations?status=pending` — это полный список, а не счётчик; при большом объёме нужен отдельный `GET /agents/tool-confirmations/count`.
- **«Треды с новыми ответами»** показывают только названия чатов: в `UnreadSnapshot.threads` нет текста корневого сообщения.
- **Меню профиля: «Что нового»** с синей точкой — нет источника «непрочитанных обновлений», точка декоративная. Нужен флаг `has_unseen_release_notes` в `User`/`preferences`.
- **Popover пространства** показывает одно пространство: multi-workspace в продукте нет; переключатель отрисован как в макете, но без списка.
- **Свёрнутая панель**: подписи/бейджи скрыты, popover открывается справа — как в макете. Аккуратно: при ширине ≤ 840 px панель принудительно сворачивается (бриф: «сжатый desktop»).

## Список чатов
- **Присутствие в строке** (зелёная точка) доступно только для собеседников, по которым realtime прислал presence (участники открытых чатов). Для остального списка точки не будет, пока сервер не начнёт слать presence по всем `direct_peer` из `GET /chats`.
- **Счётчик чатов в фильтре-чипе папки** (макет: без счётчика — ок) и **сортировка**: сервер не гарантирует порядок, сортируем на клиенте по `last_message_at`; pinned — по порядку `pinned-chats`.
- **Inline ошибка «Показаны сохранённые чаты»**: список берётся из стора после неудачного `reload`, но при первом запуске без сети список будет пуст (нет офлайн-кэша чатов в IndexedDB). Нужен кэш `chats` в `persistence.ts`.
- **Offline-pill** в шапке списка появляется, когда realtime не `live`; на мобильных скрыт.

## Беседа
- **«N участников» в подзаголовке** берётся из `GET /chats/{id}/members` (полный список). Для больших чатов нужен `member_count` в `Chat`.
- **Аватары участников треда** у ссылки «3 ответа» и «последний в 12:40»: в `Message` есть только `thread_reply_count`; нужны `thread_participants` (2–3 `actor_id`) и `thread_last_reply_at`.
- **Просмотры** («Просмотры и реакции») считаются по `receipts`; счётчика просмотров у сообщения нет.
- **Закреплено ли сообщение** определяется по `GET /chats/{id}/pins` (один запрос на чат); флага `pinned` в `Message` нет.
- **Открытие изображения**: превью кликом скачивает файл; лайтбокса в макете нет, но он напрашивается.
- **Редактирование**: inline-редактор вместо `prompt()`; история правок и «кто редактировал» в API нет.
- **Удалённое сообщение** показывается как «Сообщение удалено» без имени удалившего (модератор/автор) — в API нет `deleted_by`.
- **Поиск в чате** из шапки открывает общую палитру с фильтром по чату — отдельной панели поиска внутри беседы в макете нет.
- **Агент «читает 3 файла…»**: realtime-статус агента содержит только `state` (`thinking/tool/streaming`), без описания шага. Нужен `detail` в кадре `agent_status`.

## Композер
- **«Отправить позже…»** — в меню отправки, отключено: нет API отложенной отправки (`scheduled_at` в `CreateMessageRequest`).
- **Вложения**: лимит 10 на клиенте; превью изображений — object URL локального файла; видео-превью нет.
- **Черновики** синхронизируются с задержкой 600 мс и конфликт-версией, как раньше; индикатора «черновик» в строке чата (макет его не требует) нет.
- **Форматирование** — markdown-обёртки без WYSIWYG; в макете панель «Aa» показана как toggle, так и сделано.

## Тред
- **«Подписан»** вычисляется по `GET /threads` (список подписок). Нужен флаг `followed` в `ThreadSummary`/`Message`, чтобы не тянуть весь список.
- **Тред в канале** для читателя (`role: member`) закрыт для ответов, как и основная лента — в макете отдельный кейс не описан.

## Тёмная тема
- Макеты только light; dark собран на токенах (`packages/tokens/src/theme.css`), проверено вручную по контрасту. Нужны отдельные макеты dark, если требуется точное соответствие.
