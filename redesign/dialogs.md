# Диалоги и оверлеи — чего не хватает для полной реализации дизайна

Модуль `apps/web/src/dialogs`. Всё перечисленное реализовано «насколько позволяет API»; ниже — разрывы между макетом «Диалоги» и текущим бэкендом/продуктом.

## Поиск (command palette)
- **Счётчик участников в результатах чатов** («группа · 8 участников»). В `Chat` нет `member_count`; сейчас показываем тип чата и тему. Нужно поле `member_count` в схеме `Chat`/`DirectoryChat`.
- **Публичные каналы «вы не подписаны»**: берём из `GET /chats/discover`, но там нет ни счётчика участников, ни аватара (`avatar_seed`). Показываем иконку `#`.
- **Автор и чат у результатов поиска**: `SearchResult` содержит только `actor_id`/`chat_id`. Имя автора известно лишь для личных чатов (через `direct_peer`), в остальных случаях пишем «Участник». Нужен `actor_display_name` (как в `MessagePreview`) прямо в `SearchResult`.
- **«Показать ещё 12»**: в `SearchPage` нет общего количества (`total`), поэтому кнопка без числа и футер считает только загруженные строки.
- **Выбор чата для фильтра** внутри палитры не реализован (нет UI в макете); фильтр по чату ставится только при открытии поиска из шапки беседы и снимается чипом.
- **Присутствие людей** берётся из realtime-стора: сервер шлёт presence только для участников открытых чатов, поэтому у остальных людей точка будет «offline».

## Новый чат
- Тип «Личный» намеренно убран (личный чат открывается из поиска/участников). Для группы переключатель «Закрытая группа» выключенным состоянием создаёт `visibility: public` — в макете такой вариант не описан, подпись остаётся «Закрытая группа».
- Нет серверной проверки уникальности названия до отправки: ошибка 409 показывается общим сообщением `errorConflict`, без подстановки имени канала.

## Новая папка
- **Своя обложка (SVG/PNG)** — `ChatFolder.icon` ограничен enum из 50 иконок, загрузка обложки в API отсутствует. Плитка отрисована в disabled-состоянии.
- Нет счётчика чатов в папке в списке фильтров (только в диалоге).

## Инфо чата
- **Вложения (Медиа/Файлы)**: отдельного эндпоинта нет, используем `GET /search?q=*&type=file&chat_id=…`. Если сервер требует непустой текстовый запрос и отвергает `*`, вкладки покажут пустое состояние. Нужен `GET /chats/{id}/files?kind=media|document` с размером и превью.
- **Размер файла** в строках («2,4 МБ») недоступен: `SearchResult` не содержит `size`.
- **Ссылки** — сервер не извлекает ссылки из сообщений, вкладка всегда пустая. Нужен индекс ссылок (`GET /chats/{id}/links`) с title/favicon.
- **Закреплённые** — `GET /chats/{id}/pins` отдаёт только `message_id`, для каждого закреплённого делается `messageContext`. Нужен расширенный ответ с превью сообщения и автором.
- **Открепить** из инфо-диалога не реализовано (по макету — из меню сообщения).
- Роли участников можно только читать; смена роли/удаление участника из диалога — нет в макете, не реализовано.

## Пересылка
- Метаданные чатов в списке («группа · 14») — нет `member_count`.
- Пересылка идёт последовательными вызовами `forward` + `createMessage` для комментария; атомарной пересылки с комментарием в API нет. Частичные ошибки показываем тостом с «Повторить» для неудавшихся чатов.

## Просмотры и реакции
- Просмотры считаются по `GET /messages/{id}/receipts`; «не прочитали N» вычисляется как участники минус прочитавшие (для больших чатов список участников должен быть полным).
- Имена реагирующих/прочитавших вне списка участников чата показываются как «Участник» (нет `display_name` в `Reaction`/`MessageReceipt`).

## Статус
- Пресет «В отпуске · своё» не открывает выбор даты: в API `expires_at` есть, но в макете нет date-picker для «своё». Сейчас пресет ставит «Никогда».
- Срок «Сегодня» вычисляется на клиенте как 23:59 локального времени, а не по timezone пользователя на сервере.

## Уведомления
- Ссылка «Как разрешить?» ведёт на справку Chrome; для других браузеров нужен собственный раздел базы знаний.

## Общее
- **Отправить позже / запланированные сообщения** — в API нет; пункт остаётся disabled в композере.
- Мобильные bottom-sheet рисуются CSS-классом `ui-dialog--sheet`; жест «свайп вниз для закрытия» не реализован.
