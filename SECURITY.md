# Безопасность Coma

## Как сообщить об уязвимости

Не публикуйте уязвимость в GitHub Issues, обсуждениях или чатах. Пишите напрямую в Telegram: [@levpavloff](https://t.me/levpavloff).

В сообщении укажите:

- версию Coma (`docker compose exec core /comamessenger version`) и способ установки;
- что именно уязвимо и чем это грозит;
- шаги воспроизведения или proof of concept;
- нужно ли упоминать вас в благодарностях и под каким именем.

Не прикладывайте реальные данные пользователей, токены и содержимое `.env`.

## Что будет дальше

- В течение 3 рабочих дней подтвердим получение и скажем, кто занимается отчётом.
- В течение 10 рабочих дней оценим серьёзность и назовём срок исправления.
- Критические уязвимости исправляем в первую очередь: выпускаем патч-версию для всех поддерживаемых веток и сообщаем о ней в заметках к выпуску и в GitHub Security Advisory.
- Подробности публикуем после выхода исправления или через 90 дней после отчёта, смотря что наступит раньше. Сроки можно сдвинуть по договорённости.

Проверять уязвимости можно только на своей установке. Чужие серверы, сервисы `push.coma-chat.com` и `mail.coma-chat.com`, а также стейджинг проекта атаковать нельзя: нагрузочные тесты, перебор паролей, рассылки и доступ к чужим данным запрещены.

## Поддерживаемые версии

| Версия                                   | Исправления безопасности            |
| ---------------------------------------- | ----------------------------------- |
| последняя минорная версия (сейчас 0.1.x) | да                                  |
| предыдущая минорная версия               | 3 месяца после выхода следующей     |
| предварительные версии (`-rc`)           | нет, обновитесь на ближайший выпуск |
| более старые                             | нет                                 |

До версии 1.0 исправления выходят только в последней минорной ветке. Обновляйтесь по [docs/upgrade.md](docs/upgrade.md).

## Что мы делаем сами

- Образы собираются в GitHub Actions из тега выпуска. К ним прилагаются SBOM и provenance, а подпись делается через cosign без ключей, по OIDC GitHub. Как проверить подпись, написано в заметках к выпуску.
- Образы запускаются не от root, на минимальных базах (distroless, nginx-unprivileged), базовые образы закреплены по digest.
- Установка по умолчанию открывает наружу только 80 и 443. База, Redis, хранилище и Core доступны только внутри сети Docker.

## Reporting in English

Please report vulnerabilities privately via Telegram [@levpavloff](https://t.me/levpavloff), not in public issues. We acknowledge within 3 business days. Security fixes go to the latest minor release line.
