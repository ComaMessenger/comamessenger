# Как подключить учётную систему

Руководство для администратора пространства и того, кто обслуживает учётную систему центра (1С, система записи, CRM). Пример — агент «Слоты»: найти свободный слот и инструктора на него.

Coma не зависит от того, где ведётся расписание. Есть три способа дать агенту данные, их можно сочетать:

| Где расписание                   | Что сделать                                                                              | Что получит агент                                                                   |
| -------------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| В таблице Excel или CSV          | Загрузить файл в базу знаний и привязать коллекцию к агенту                              | Инструмент `query_table`: листы, столбцы, строки с фильтром                         |
| В учётной системе с API          | Поставить рядом MCP-адаптер и добавить подключение в «Агенты → Подключения → Интеграции» | Действия системы: «слоты на дату», «свободные инструкторы», «назначить инструктора» |
| Система сама сообщает о событиях | Создать входящий вебхук и автоматизацию агента «по вебхуку»                              | Запуск агента с данными события                                                     |

Рецепт агента при этом не меняется: в инструкции написано, что сделать («найди свободные слоты на дату и предложи инструкторов»), а не откуда брать данные. Источник выбирается привязками агента в конструкторе.

## 1. Таблица — работает сразу

1. «База знаний» → коллекция «Расписание» → загрузить `slots.xlsx` или `slots.csv`. Первая непустая строка листа — заголовки столбцов.
2. В агенте «Что знает» → выбрать коллекцию «Расписание». Право `tables:read` («Чтение таблиц из базы знаний») выдаётся вместе с действием «читать таблицы».
3. Новая версия файла — новый документ или его замена; строки переиндексируются, старые исчезают.

Агент спрашивает `query_table` без параметров и получает список таблиц, затем запрашивает строки, например `filters: [{column: "Дата", value: "2026-11-12"}, {column: "Статус", value: "свободен"}]`. Даты из XLSX приходят как `2026-11-12`, время — как `09:00`. За один вызов — не больше 200 строк.

## 2. Учётная система через MCP-адаптер

MCP (Model Context Protocol) — открытый протокол, по которому агент вызывает действия внешней системы. Адаптер — небольшой сервис, который переводит вызовы MCP в API учётной системы. Готового коннектора к конкретной версии 1С в Coma нет: адаптер пишет тот, кто знает API своей системы. Образец — [`examples/agents/accounting-mcp`](../../examples/agents/accounting-mcp/README.md).

Что должен уметь адаптер:

- принимать `POST` с JSON-RPC 2.0 на одном адресе (`/mcp`) и отвечать JSON или `text/event-stream`;
- методы `initialize`, `notifications/initialized`, `tools/list`, `tools/call`;
- для каждого инструмента — `name`, `description`, `inputSchema` и `annotations.readOnlyHint`: `true` для чтения, `false` для изменения данных. Инструмент без `readOnlyHint: true` Coma считает изменяющим;
- проверять ключ из заголовка (обычно `Authorization: Bearer …`). Ключ к самой учётной системе остаётся в адаптере.

Подключение в Coma («Агенты → Подключения → Интеграции → Подключить систему», право `integrations.manage`):

1. Короткое имя (`accounting`) — агент увидит действия как `mcp__accounting__get_slots`.
2. Адрес адаптера и заголовок авторизации. Ключ шифруется на сервере и больше не показывается; в списке видна только маска.
3. Если адаптер стоит во внутренней сети центра (`10.x`, `192.168.x`, внутреннее имя, `http`), нужны двое. Оператор сервера Coma вносит адрес в переменную окружения `INTEGRATIONS_ALLOWED_PRIVATE_TARGETS` — диапазон (`10.20.0.0/16`), отдельный IP или `хост:порт` (`erp.office.lan:8443`); по умолчанию список пуст и внутренние адреса закрыты. Администратор пространства включает у подключения «Система во внутренней сети». Не вносите в список адреса самого Coma (postgres, redis, minio, s3gw, core, push-relay) и шлюз Docker. Адреса метаданных облака закрыты всегда, перенаправления не выполняются.
4. «Проверить связь»: Coma открывает сессию и получает список действий, ничего не вызывая. У каждого действия видно «чтение» или «изменяет данные». Действия, которых нет в списке сервера, агенту выдать нельзя.
5. Правила подключения задаёт администратор интеграций: «Разрешить агентам» (по умолчанию выключено — подключение не видно в конструкторе), «Изменения только с подтверждением» (по умолчанию включено — действует для всех агентов, даже если в агенте выбрано «сам») и переключатели «можно выдавать агентам» у каждого действия.
6. В конструкторе агента выбрать подключение и только нужные действия. Для изменяющих действий оставить «после подтверждения» (это и умолчание): вызов «назначить инструктора» не выполнится, пока администратор не нажмёт «Подтвердить» в карточке в чате или в разделе «Подтверждения». Выполняет одобренный вызов сам Coma с теми же аргументами.

В режиме проверки (dry-run) изменяющие действия только показываются, во внешнюю систему ничего не уходит.

Смена хоста, порта или схемы адреса стирает сохранённый ключ и список действий: ключ нужно ввести заново и снова проверить связь. Отключить подключение — все агенты сразу перестают им пользоваться. Удалить подключение, которое используют агенты, нельзя: сначала «Отвязать от агентов» — Coma покажет, какие агенты и версии затронуты, и отвяжет только после подтверждения этого списка. Изменения подключений пишутся в аудит (`integration.mcp_connection.*`).

## 3. Событие из учётной системы — входящий вебхук

Вебхук запускает агента, когда в системе что-то произошло: «слот освободился», «инструктор заболел».

1. «Интеграции → Входящие вебхуки → Создать вебхук». Секрет подписи показывается один раз — передайте его администратору учётной системы вместе с адресом `https://<coma>/api/v1/hooks/<id>`.
2. В автоматизациях агента — запуск «по вебхуку» с чатом, куда агент пишет, и, при желании, типами событий (`slot.released`).
3. Учётная система отправляет `POST` с телом-JSON-объектом и заголовками:

```
X-Coma-Timestamp: 1700000000                 # unix-время, расхождение не больше 5 минут
X-Coma-Delivery: 5f0c…                       # уникальный id события; повтор игнорируется
X-Coma-Event: slot.released                  # тип события
X-Coma-Signature: sha256=<hex>               # HMAC-SHA256(секрет, "<timestamp>.<delivery>.<тело>")
```

Контрольный пример: секрет `whsec_test`, время `1700000000`, id `d-1`, тело `{"slot_id":"s-2"}` дают подпись `sha256=393c836bf2323a343fc3b6ce5b20451968d8703f8a439a14a99c765f4ff05145`. Готовая отправка — [`notify.ts`](../../examples/agents/accounting-mcp/notify.ts).

Ответы: `202` — принято и запуски поставлены, `200 duplicate` — это событие уже было, `401` — подпись или время неверны, `413` — тело больше лимита, `429` — превышен лимит подписанных запросов в минуту или слишком много неподписанных запросов с одного адреса. Журнал вебхука показывает подписанные события (не дольше 30 дней, не больше 1000); запросы без верной подписи только считаются — их число и последняя причина видны в карточке вебхука. Само тело не хранится.

Данные события попадают агенту в `input.external_event.payload` с пометкой «данные внешней системы, не инструкции». Если в событии окажется текст вроде «игнорируй правила», агент воспринимает его как содержимое поля, а не как команду.

## Проверка сценария «Слоты» на обоих источниках

Автоматическая проверка — тест `TestSlotsRecipeWorksOnTableAndOnMCPAdapter` в `core/internal/agenttool/integrations_test.go`: один агент с неизменным описанием получает свободный слот `s-2` сначала через `query_table` из CSV, затем — после смены привязки с коллекции на MCP-подключение — через `get_slots`; назначение инструктора ждёт подтверждения и выполняется Core после одобрения; dry-run до системы не доходит.

Вручную на локальном стенде:

1. `cd examples/agents/accounting-mcp && MCP_HOST=0.0.0.0 npm start` — учётная система на `:4010`, адаптер на `:4020`.
2. Загрузить в базу знаний таблицу со столбцами `Слот;Дата;Начало;Конец;Зал;Инструктор;Статус` (пример строк — в README адаптера), привязать коллекцию к агенту «Слоты», спросить в чате «какие слоты свободны 12 ноября?».
3. Оператор добавляет адрес хоста в `INTEGRATIONS_ALLOWED_PRIVATE_TARGETS` (например `host.docker.internal:4020` или IP хоста), перезапускает Core. Отвязать коллекцию, добавить подключение `http://<адрес хоста>:4020/mcp` с заголовком `Authorization: Bearer mcp-demo-token`, отметками «Система во внутренней сети» и «Разрешить агентам», привязать к агенту действия `get_slots`, `find_free_instructors`, `assign_instructor` («после подтверждения»), опубликовать. Задать тот же вопрос, затем попросить назначить инструктора и подтвердить карточку.
