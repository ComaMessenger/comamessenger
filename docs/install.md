# Установка Coma на свой сервер

Инструкция для администратора, который ставит Coma для своей компании. Coma ставится из готовых образов, исходники и сборка не нужны. Установка занимает около 30 минут, из них 10 уходит на скачивание образов.

После установки сотрудники открывают Coma в браузере по адресу вида `https://chat.company.ru` и в мобильном приложении. Переписка и файлы хранятся на вашем сервере.

## Что нужно

**Сервер.** На 100 сотрудников хватит 2 vCPU, 4 ГБ памяти и 40 ГБ SSD. Больше всего места занимают файлы: по умолчанию под них отведено 20 ГБ (`LOCAL_STORAGE_QUOTA_BYTES` в `.env`). Процессор x86-64 или ARM64.

**Система.** Linux с Docker Engine 24 или новее и Docker Compose 2.20 или новее. Инструкция проверена на Ubuntu 24.04. На Debian 12 и Ubuntu 22.04 команды те же.

**Домен.** Отдельное имя для Coma, например `chat.company.ru`. Без домена Coma работает только в пробном режиме, см. [«Пробный запуск без домена»](#пробный-запуск-без-домена).

**Сеть.**

- Входящие порты 80 и 443 открыты из интернета. Через порт 80 Let's Encrypt проверяет домен, а мобильное приложение подключается к серверу через интернет.
- Сервер может ходить в интернет: `ghcr.io` и `registry-1.docker.io` (образы), `acme-v02.api.letsencrypt.org` (сертификат), `push.coma-chat.com` (push на телефоны), `mail.coma-chat.com` (письма).

## 1. Домен

В панели DNS создайте A-запись для `chat.company.ru` с IP-адресом сервера. Если у сервера есть IPv6, добавьте ещё AAAA-запись.

Проверьте с любого компьютера:

```sh
dig +short chat.company.ru
```

Команда должна вывести IP сервера. Новая запись появляется через 5–30 минут, до этого сертификат не выпустится.

## 2. Docker

Подключитесь к серверу по SSH под root или пользователем с `sudo` и поставьте Docker официальным скриптом:

```sh
curl -fsSL https://get.docker.com | sh
docker compose version
```

Вторая команда выводит версию Compose. Если она ниже 2.20, обновите пакет `docker-compose-plugin`.

## 3. Скачать Coma

Номер последней версии указан на [странице выпусков](https://github.com/ComaMessenger/comamessenger/releases). Ниже вместо `0.1.0` подставьте его.

```sh
mkdir -p /opt/coma && cd /opt/coma
curl -fsSL https://github.com/ComaMessenger/comamessenger/releases/download/v0.1.0/coma-deploy-0.1.0.tar.gz \
  | tar xz --strip-components 1
ls
```

В папке появятся:

| Файл                                            | Для чего                                                      |
| ----------------------------------------------- | ------------------------------------------------------------- |
| `compose.yaml`                                  | какие сервисы запускать; образы закреплены по версии и digest |
| `.env.example`                                  | образец настроек                                              |
| `generate-env.sh`                               | создаёт `.env` с паролями и ключами                           |
| `Caddyfile`                                     | HTTPS с автоматическим сертификатом                           |
| `backup.sh`, `restore.sh`                       | резервная копия и восстановление                              |
| `upgrade.sh`                                    | обновление на новую версию                                    |
| `nginx.conf.example`, `compose.host-proxy.yaml` | если на сервере уже есть nginx                                |

Целостность архива можно проверить по `SHA256SUMS` со страницы выпуска.

## 4. Настройки

```sh
./generate-env.sh chat.company.ru
```

Скрипт создаёт `.env`: генерирует пароли базы и ключи шифрования, прописывает адрес и выставляет файлу права `0600`. Ещё он скачивает образ Core и создаёт им ключи Web Push. Секреты на экран не выводятся. Существующий `.env` скрипт не перезаписывает.

Флаги:

- `--agents` включает ИИ-агентов. Ключ модели (OpenAI-совместимый провайдер) администратор потом вводит в настройках пространства.
- `--s3` хранит файлы во встроенном S3-хранилище, а не в томе Docker. Обычно это не нужно, см. [«Где хранятся файлы»](#где-хранятся-файлы).

> **`.env` это главный файл установки.** В нём пароль базы и ключ, которым зашифрованы пароли интеграций. Без прежнего `.env` база из копии не откроется, а пароли SMTP, S3 и ключи моделей придётся вводить заново. Скрипт резервного копирования сохраняет `.env` вместе с базой. Не заводите новый `.env` для уже работающей установки.

## 5. Запуск

```sh
docker compose up -d --wait
```

Первый раз команда работает 2–5 минут: скачивает образы, создаёт базу и получает сертификат. Когда она закончится, проверьте:

```sh
docker compose ps
curl https://chat.company.ru/healthz
```

У всех сервисов должен быть статус `healthy`, а `curl` должен ответить `{"status":"ok"}`. Если что-то не так, смотрите [«Частые ошибки»](#частые-ошибки).

Сервисы запускаются заново после перезагрузки сервера. Наружу открыты только порты 80 и 443. База, Redis и Core доступны только внутри Docker.

## 6. Первый администратор

Откройте `https://chat.company.ru` в браузере. На чистой установке там экран «Сервер ещё не настроен».

1. В поле **Bootstrap token** вставьте одноразовый код установки. Он хранится на сервере:

   ```sh
   grep BOOTSTRAP_TOKEN /opt/coma/.env
   ```

   Копируйте всё, что после `=`.

2. Заполните название организации, имя владельца, почту и пароль.
3. Нажмите «Создать». Владелец получает все права и попадает в Coma.

Код срабатывает один раз. Пока владелец не создан, без кода экран не пропустит никого, даже того, кто первым откроет адрес. После создания экран настройки больше не показывается.

## 7. Сотрудники

Владелец приглашает людей в **Настройки → Пространство → Приглашения**. Письмо с приглашением уходит через почтовый сервис Coma, настраивать почту не нужно. Ссылку из приглашения можно скопировать и переслать самому, например в корпоративный чат.

Сотрудник открывает ссылку, вводит имя и пароль и попадает в пространство.

Если хотите слать письма со своего почтового сервера, укажите SMTP в **Настройки → Пространство → Почта**.

## 8. Вход с телефона

Установите приложение Coma на iPhone (TestFlight, позже App Store) или Android. При первом запуске введите адрес сервера `chat.company.ru` или откройте на телефоне ссылку-приглашение: приложение возьмёт адрес из неё.

Push-уведомления включены сразу. Сервер отправляет их через сервис Coma `push.coma-chat.com`. Текст сообщений шифруется на сервере, поэтому сервис видит только служебный адрес устройства. Отключить push на телефоны можно строкой `PUSH_RELAY_URL=off` в `.env`.

Приложению нужен HTTPS-адрес, доступный из интернета. По IP или внутреннему имени оно не подключится.

## 9. Резервные копии

Копия включает базу, файлы и `.env` с ключами. Без копии один сбой диска уничтожит всю переписку.

```sh
cd /opt/coma
cp backup.env.example backup.env   # куда класть, сколько хранить, выгрузка в S3
./backup.sh
```

Архив появится в `backups/`. Скрипт проверяет, что дамп базы читается, и оставляет 14 последних копий (`BACKUP_KEEP`).

Каждую ночь в 03:15:

```sh
( crontab -l 2>/dev/null; echo '15 3 * * * cd /opt/coma && ./backup.sh >> backups/backup.log 2>&1' ) | crontab -
```

Храните копии и вне этого сервера. Скрипт сам выгружает архив в S3-совместимое хранилище (Yandex Object Storage, Selectel, VK Cloud) и шифрует его паролем, если это задано в `backup.env`. Восстановление и проверка копии описаны в [docs/backup.md](backup.md).

## 10. Обновление

```sh
cd /opt/coma
./upgrade.sh 0.2.0
```

Скрипт скачивает файлы новой версии и проверяет контрольные суммы. Затем делает резервную копию, скачивает образы и перезапускает Coma. `.env` не меняется. Откат и порядок действий при сбое описаны в [docs/upgrade.md](upgrade.md).

## Где хранятся файлы

Обычно файлы лежат в томе Docker `coma_files-data` на диске сервера. Для 100 человек этого достаточно, и бэкап сохраняет файлы вместе с базой.

Если файлы должны лежать во внешнем S3-хранилище, впишите в `.env` `STORAGE_DRIVER=s3` и параметры `S3_*`. Пример есть в комментариях `.env.example`. Бакет создайте заранее и разрешите в CORS методы GET, PUT и HEAD с адреса `PUBLIC_APP_URL`, открыв заголовок `ETag`. За копии такого бакета отвечает провайдер: включите версионирование или репликацию.

Перенос уже загруженных файлов из тома в S3 ещё не автоматизирован. Решите, где хранить файлы, до того как сотрудники начнут ими пользоваться.

## Агенты

Если при установке не указали `--agents`, добавьте `agents` в `COMPOSE_PROFILES` в `.env` (`COMPOSE_PROFILES=caddy,agents`) и выполните `docker compose up -d --wait`. Ключ модели и лимиты расходов настраиваются в веб-интерфейсе. В `.env` задаются только общие потолки `ARCHITECT_DAILY_COST_LIMIT` и `ARCHITECT_MONTHLY_COST_LIMIT`.

## Свой nginx вместо Caddy

Если порты 80 и 443 на сервере уже занимает nginx:

1. В `.env` уберите `caddy` из `COMPOSE_PROFILES` и раскомментируйте `COMPOSE_FILE=compose.yaml:compose.host-proxy.yaml`. Core будет слушать `127.0.0.1:8080`, веб будет на `127.0.0.1:8081`. Если эти порты заняты, поменяйте `CORE_HOST_PORT` и `WEB_HOST_PORT`.
2. Возьмите `nginx.conf.example` и замените в нём `chat.example.com` на свой домен. В файле уже настроены WebSocket, загрузка файлов до 110 МБ и отключение журнала для ссылок-приглашений.
3. Получите сертификат (`certbot --nginx -d chat.company.ru`), выполните `nginx -t` и `systemctl reload nginx`.
4. `docker compose up -d --wait`.

## Пробный запуск без домена

Чтобы посмотреть Coma на своём компьютере:

```sh
./generate-env.sh localhost:8088
docker compose up -d --wait
```

Откройте `http://localhost:8088`. Это пробный режим по HTTP: мобильное приложение, письма и Web Push в нём не работают. Для настоящей установки начните заново с доменом: `docker compose down -v`, удалите `.env` и выполните шаги 4–5.

## Частые ошибки

Подробности всегда есть в журнале: `docker compose logs core --tail 50`. Если Core не может запуститься, он пишет абзац с причиной и подсказкой, начинающийся словами `Coma … cannot start`.

| Что видно                                                                                           | Причина и что делать                                                                                                                                                                                                       |
| --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Set COMA_VERSION in .env` или `Run ./generate-env.sh first`                                        | Нет `.env` или он неполный. Выполните шаг 4.                                                                                                                                                                               |
| Браузер пишет, что сертификат недействителен, в `docker compose logs caddy` есть `challenge failed` | Домен ещё не указывает на сервер или порт 80 закрыт. Проверьте `dig +short chat.company.ru` и файрвол (`ufw allow 80,443/tcp`), затем `docker compose restart caddy`.                                                      |
| `Bind for 0.0.0.0:80 failed: port is already allocated`                                             | Порт занят другим веб-сервером. Остановите его или настройте [свой nginx](#свой-nginx-вместо-caddy).                                                                                                                       |
| `PostgreSQL rejected the password from DATABASE_URL`                                                | `.env` создан заново, а база осталась от прошлой установки. Пароль базы задаётся один раз при её создании. Верните прежний `.env` из резервной копии. Если данных в базе нет: `docker compose down -v` и повторный запуск. |
| `BOOTSTRAP_TOKEN must be set…`, `… must not use the development default`                            | В `.env` пустые или учебные секреты. Создайте `.env` скриптом `generate-env.sh`.                                                                                                                                           |
| `PUBLIC_APP_URL uses http:// but AUTH_COOKIE_SECURE=true`                                           | Адрес без HTTPS, а cookie требуют HTTPS. Укажите `https://` или для пробы `AUTH_COOKIE_SECURE=false`.                                                                                                                      |
| `database schema is newer than this Core`                                                           | Запущена версия старше той, что уже обновила базу. Вернитесь на новую версию или восстановите копию, сделанную до обновления ([docs/upgrade.md](upgrade.md)).                                                              |
| `file storage check failed`                                                                         | Недоступно S3-хранилище или бакет не создан. Проверьте `S3_*` в `.env`.                                                                                                                                                    |
| Экран настройки пишет «Bootstrap token не принят сервером»                                          | Код скопирован не полностью. Выполните `grep BOOTSTRAP_TOKEN .env` и скопируйте значение после `=`.                                                                                                                        |
| Приглашения не приходят на почту                                                                    | Почтовому сервису нужен HTTPS-адрес, открытый из интернета: он проверяет домен через `/api/v1/mail-relay/challenge`. Статус виден в **Настройки → Пространство → Почта**. Ссылку из приглашения можно отправить вручную.   |
| Телефон не подключается                                                                             | Нужен HTTPS и домен, доступный из интернета. Проверьте `https://chat.company.ru/healthz` с телефона через мобильный интернет.                                                                                              |

## Что где лежит

- `/opt/coma/.env`: настройки и ключи (права `0600`).
- Тома Docker: `coma_postgres-data` (база), `coma_files-data` (файлы), `coma_caddy-data` (сертификаты).
- `/opt/coma/backups/`: резервные копии.
- `/opt/coma/releases/<версия>/`: файлы предыдущих версий, `upgrade.sh` берёт их при откате.

`docker compose down -v` удаляет тома вместе с базой и файлами. Для остановки используйте `docker compose down` без `-v`.

Сообщить об ошибке: [GitHub Issues](https://github.com/ComaMessenger/comamessenger/issues). Об уязвимостях пишите не в Issues, а по [SECURITY.md](../SECURITY.md).
