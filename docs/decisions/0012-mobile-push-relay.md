# ADR-0012: push-relay для мобильных клиентов self-hosted инстансов

- Статус: принято
- Дата: 2026-09-29

## Контекст

Web Push (ADR-0010) работает с ключами VAPID самого инстанса. У мобильных push другая модель: APNs и FCM принимают сообщения только от владельца приложения в сторе. Ключи издателя Coma нельзя раздать каждому self-hosted инстансу, а требовать от администратора собственный Firebase-проект и Apple-сертификат можно только при собственной сборке приложения.

## Решение

Проект Coma эксплуатирует push-relay (`push.<домен Coma>`), исходный код которого лежит в этом репозитории. Инстанс не знает raw device token, а relay не видит содержимое уведомлений.

### Регистрация

1. Приложение получает APNs/FCM token и само регистрирует его в relay. Relay возвращает непрозрачный `relay_handle` (случайный, 256 бит) и хранит только пару handle → platform/token.
2. Приложение генерирует симметричный ключ уведомлений и хранит его в secure storage.
3. Приложение регистрирует на инстансе устройство: `relay_handle`, ключ уведомлений, platform, app version, locale. Устройство привязано к session: logout, revocation и смена пароля удаляют его.
4. При ротации platform token приложение обновляет запись в relay; handle не меняется.

### Доставка

- Worker из ADR-0010 материализует доставки на мобильные устройства так же, как на browser subscriptions: те же membership, `push_enabled`, `notify_level`, mute, mentions и active-screen lease.
- Инстанс шифрует payload ключом устройства (AEAD). Внутри — автор, чат, deep link, счётчик непрочитанного и текст только при включённом `push_preview`.
- Relay получает `relay_handle`, зашифрованный blob и нейтральный fallback-текст («Новое сообщение»). iOS расшифровывает payload в Notification Service Extension, Android — в обработчике FCM data message. Если расшифровка невозможна, показывается fallback.
- Relay не логирует payload, ограничивает частоту по handle и по IP инстанса, отвечает `410` на неизвестный или удалённый handle; инстанс удаляет такое устройство.

### Конфигурация инстанса

- `PUSH_RELAY_URL` по умолчанию указывает на relay проекта; значение `off` отключает мобильные push (изолированные контуры).
- Собственная сборка приложения с собственными ключами и собственным relay — будущая платная white-label граница; протокол relay от этого не меняется.
- Privacy-раздел документации описывает, какие данные видит relay: handle, platform token, время и размер доставки, IP инстанса.

## Последствия

- У проекта появляется production-сервис с доступностью и расходами; его недоступность задерживает только мобильные push, но не сообщения и не realtime.
- Компрометация relay раскрывает platform tokens и метаданные доставки, но не содержимое сообщений и не имена чатов.
- Инстанс не может отправить push на устройство, которое не зарегистрировалось у него само.
- Notification Service Extension добавляется через Expo config plugin (ADR-0011).
