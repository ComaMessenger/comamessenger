# ADR-0011: стек мобильного клиента

- Статус: принято
- Дата: 2026-09-29

## Контекст

Фаза 6 выпускает iOS/Android клиент поверх `packages/core` и `packages/tokens` (ADR-0009). Клиент подключается к произвольному self-hosted инстансу, поэтому адрес сервера, deep links и push не могут зависеть от одного домена. Приложение публикуется с личных (individual) аккаунтов Apple Developer и Google Play; первая версия поддерживает только телефоны.

## Решение

### Платформа

- Expo (SDK 57 на момент решения) с Continuous Native Generation: каталоги `ios/` и `android/` генерируются `expo prebuild` и не коммитятся, нативные изменения делаются config plugins.
- Сборки и подпись — EAS Build; credentials живут в EAS, а не в репозитории. Для разработки используется development build, а не Expo Go.
- Приложение живёт в `apps/mobile` в общем pnpm workspace и импортирует `@comamessenger/core`, `@comamessenger/protocol` и `@comamessenger/tokens` напрямую.
- Минимальные версии: iOS 16, Android 8.0 (API 26). Только телефоны: `supportsTablet: false`, портретная ориентация.

### Интерфейс

- Навигация — `expo-router`: файловые маршруты совпадают по смыслу с web (`/chat/[chatId]`, `/chat/[chatId]/thread/[threadId]`) и дают deep links без отдельного parser.
- Вёрстка — `StyleSheet` против значений `@comamessenger/tokens`. Tamagui, NativeWind и универсальный UI-пакет не используются: на старте фазы общих с web компонентов нет, пересечение — только tokens и engine (точка пересмотра ADR-0009 закрыта).
- Лента сообщений — `@shopify/flash-list`; выбор перепроверяется профилированием длинной ленты в M2, альтернатива — LegendList.
- Жесты — `react-native-gesture-handler` + `react-native-reanimated`, клавиатура — `react-native-keyboard-controller`, haptics — `expo-haptics`.
- Анимации логотипа — Lottie; SMIL-исходники конвертируются один раз.
- Локализация — i18next + i18next-icu, RU/EN. Общие с web доменные строки выносятся в пакет, когда появится реальное пересечение.

### Сессия и хранилище

- `MessengerAPI` создаётся с `RefreshTokenStore`: запросы идут с `X-Coma-Client: native` без cookies, refresh-токен хранится в `expo-secure-store` (Keychain/Keystore) и не попадает в UI-state.
- Outbox, realtime checkpoint и ограниченный кэш последних чатов — `expo-sqlite` с версионируемой схемой. AsyncStorage не используется для данных сессии.
- Одновременно приложение подключено к одному серверу; смена сервера равна выходу.

### Адрес сервера и ссылки

- Первый экран — адрес инстанса. Клиент проверяет `/healthz` и публичный branding endpoint до показа логина.
- Custom scheme `coma://` — основной вход в приложение из ссылок. Universal/App Links работают только на домене издателя: `https://<домен Coma>/open?server=…&path=…` открывает приложение или показывает страницу установки. Домены self-hosted инстансов в entitlements не попадают.
- Web-страница приглашения инстанса предлагает «Открыть в приложении» со ссылкой, содержащей адрес сервера и токен.

### Объём мобильного клиента

Администрирование пространства, конструктор агентов, брендинг, инфраструктура и аудит остаются в web; приложение открывает их в браузере. Агенты в мобильном клиенте — участники чатов со статусами и стримингом.

## Последствия

- Нативный код не поддерживается вручную; обновление Expo SDK — отдельная задача с перегенерацией проектов.
- Имя продавца в App Store и Google Play — имя владельца личного аккаунта. Перевод на организацию потребует переноса приложения между аккаунтами.
- Bundle ID фиксируется до первой внутренней сборки и после этого не меняется; он зависит от выбора публичного домена Coma.
- Push-уведомления требуют издательских ключей APNs/FCM; схема доставки описана в ADR-0012.
