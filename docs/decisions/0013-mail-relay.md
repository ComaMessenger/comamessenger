# ADR-0013: почтовый сервис Coma через RuSender

- Статус: принято
- Дата: 2026-11-16
- План: [фаза 7.1](../phases/07.1-mail-relay.md), эксплуатация — [runbook](../runbooks/mail-relay.md)

## Контекст

Coma шлёт пять видов писем: приглашение, сброс пароля, подтверждение новой почты,
уведомление старому адресу о смене почты и дайджест пропущенного. До этого решения
каждое пространство подключало свой SMTP в «Инфраструктуре». Без SMTP не работали
восстановление пароля и письма с приглашениями, а администратор маленькой команды
редко знает, где взять SMTP с настроенными SPF и DKIM.

Владелец продукта решил 2026-11-14: установка по умолчанию шлёт письма через сервис
Coma, свой SMTP остаётся альтернативой. Условия решения записаны в
[`backlog.md`](../backlog.md), раздел «Почтовый relay Coma».

## Решение

### Отдельный сервис, а не общий SMTP-логин

Проект эксплуатирует `mail-relay` на `https://mail.coma-chat.com`. Код лежит в этом
репозитории (`core/cmd/mail-relay`, `core/internal/mailrelay`), как у push-relay
(ADR-0012). Установка получает свой ключ и не получает учётных данных поставщика.

Отклонённые варианты:

- **Раздать установкам SMTP-логин поставщика.** Логин один на всех. Утечка из любой
  установки отдаёт домен `coma-chat.com` спамерам, а лимиты и отзыв по одной
  установке невозможны.
- **Слать письма из core напрямую в API поставщика.** Тот же ключ на каждой машине.
- **Только свой SMTP.** Так было; это главный барьер для маленьких команд.

### Поставщик: HTTP API RuSender

- Адрес: `POST https://api.rusender.ru/api/v1/public/emails`, заголовок
  `Authorization: Bearer rs_ck_v1_…`. Токену нужно одно право — `email.send`.
- Почему API, а не SMTP RuSender: `Idempotency-Key` (повтор не даёт второго письма),
  машинные коды ошибок (`RECIPIENT_SUPPRESSED`, `RATE_LIMIT_EXCEEDED` с `Retry-After`,
  `PAYMENT_REQUIRED`), статус каждого получателя в ответе, `emailId` для связи с
  вебхуками.
- Пятизначное `RUSENDER_SECOND_KEY` из файла владельца — по документации это
  `keyId`: числовой id ключа отправки (бейдж «ID …» на карточке ключа в разделе
  «Транзакционные отправки»). Поле необязательное: без него RuSender берёт ключ
  домена из `from.email`. Сервис передаёт `keyId`, если задан `RUSENDER_KEY_ID`, чтобы
  письма шли через выбранный ключ и попадали в его статистику и списки отписок.
- Лимиты RuSender: 600 запросов в минуту на токен, 20 писем в секунду на домен, квота
  писем в месяц на аккаунт (бесплатно — 100). Месячная квота — главный внешний
  предел; сервис отдаёт `PAYMENT_REQUIRED` установке как временный отказ.
- Вебхуки RuSender (`email.delivered`, `bounced`, `failed`, `suppressed`,
  `unsubscribed`, `complained`) приходят без подписи. Сервис принимает их по адресу с
  секретом в пути (`/v1/webhooks/rusender/{secret}`, сравнение за постоянное время).

### Отправитель

`From: «<Пространство> через Coma» <no-reply@coma-chat.com>`. Домен `coma-chat.com`
подтверждён в RuSender: SPF с `include:rsndr.ru`, DKIM `mdmdmail._domainkey`, DMARC
`p=none` (проверено 2026-11-16, подробности в плане фазы). `Reply-To` не ставится:
ответить на служебное письмо некому. Свой домен отправителя — только через свой SMTP.

### Модель доверия

Сервис не доверяет установке ничего, кроме типа письма и полей данных.

1. **Ключ установки.** `POST /v1/installations` выдаёт `installation_id` и ключ
   `cmr_…` (32 случайных байта). Сервис хранит SHA-256 ключа, сам ключ — только у
   установки, в её базе в зашифрованном виде. Регистрация ограничена по IP.
2. **Подтверждение адреса установки.** При регистрации установка называет свой
   `PUBLIC_APP_URL`. Сервис выдаёт `challenge`, затем сам запрашивает
   `GET {app_url}/api/v1/mail-relay/challenge` и сверяет ответ. Только после этого ключ
   активен. Адрес — только `https://` на порту 443, хост — публичный (запрос идёт
   через `netguard`: без редиректов, без внутренних и metadata-адресов), имя домена, а не IP;
   базовый путь — не больше одного короткого сегмента из строчных латинских букв и
   дефиса. Хост
   приводится к одному виду (нижний регистр, punycode, без точки в конце и порта
   443). Лимиты и блокировки считаются по зарегистрированному домену (eTLD+1): у
   `a.evil.ru` и `b.evil.ru` один бюджет. Новая регистрация того же адреса заменяет
   прежнюю, старый ключ получает `403 installation_replaced`; другой путь на том же
   хосте — отдельная установка и никого не заменяет. Установка без публичного
   HTTPS-адреса почтой Coma не пользуется — для неё остаётся SMTP.
3. **Ссылки только на свой адрес.** Каждая ссылка в данных письма должна начинаться с
   подтверждённого адреса установки и вести на путь своего типа: приглашение —
   `/invite/…`, сброс — `/reset-password?token=…`, подтверждение —
   `/settings/security?email_token=…`, дайджест — корень и `/settings/notifications`.
   Чужая ссылка — `400 invalid_link`. Так сервис не становится рассыльщиком
   фишинговых ссылок от имени `coma-chat.com`.
4. **Только шаблоны.** Произвольные тема, HTML и текст не принимаются. Сервис
   собирает письмо сам из своего шаблона (пакет `mailtemplate`). Строки от
   пользователей (название пространства, имя пригласившего) обрезаются, теряют
   управляющие символы и переводы строк, приводятся к NFKC. Если в строке есть адрес
   сайта или почты (в том числе с «точками-двойниками» вроде `．` и `·` или словом
   dot), мессенджер или номер телефона (7 цифр и больше), строка заменяется
   нейтральной («Coma» для пространства, «Коллега» для пригласившего): имя
   пространства видно получателю в поле «От» и теме. В HTML всё экранирует
   `html/template`, а под кнопкой стоит не сырая ссылка, а «Ссылка ведёт на сайт
   <хост>».
5. **Отзыв.** Оператор отзывает домен установки командой `mail-relay revoke` и
   возвращает командой `restore`; отозванный домен не может зарегистрироваться
   заново. Автоматически домен приостанавливается на 72 часа, если за 7 дней
   пожаловались 3 разных получателя и жалобы составили не меньше 0,3 % писем, или
   если жёстких отказов больше 10 % среди не меньше 30 писем. Порог по разным людям
   не даёт одному недоброжелателю остановить чужую установку тремя кликами «Спам».
   Приостановленный ключ получает `403 installation_revoked`, установка показывает
   это в настройках и предлагает свой SMTP; по истечении срока почта Coma
   включается сама.
6. **Получатель.** Лимиты и список отписок считаются по каноническому адресу: без
   `+метки`, без точек у Gmail, домены Яндекса как один (и `.` = `-`), домен в
   punycode. Письмо уходит на адрес как есть.
7. **Возраст и платформы.** Возраст для лимитов считается по первой проверке домена,
   перерегистрация его не сбрасывает. Домены под частными публичными суффиксами
   (`pages.dev`, `github.io`, `onrender.com` и т. п. из Public Suffix List) получают
   минимальный лимит навсегда: такие поддомены бесплатны для всех.

### Лимиты

Окно — скользящие 24 часа. Резерв лимита и запись письма идут в одной транзакции под
advisory-блокировками домена и получателя, гонка двух запросов лимит не обходит.
Сбой RuSender снимает резерв, поэтому письмо, которое не ушло, лимит не тратит.
Повтор того же запроса идёт в RuSender с тем же `Idempotency-Key`, поэтому
потерянный ответ не превращается во второе письмо.

| Что ограничено                                  | Значение                     |
| ----------------------------------------------- | ---------------------------- |
| Писем одному получателю от одного домена        | **6** в сутки                |
| …из них приглашений / сбросов / подтверждений   | 2 / 3 / 3                    |
| …из них дайджестов                              | 2                            |
| Писем одному адресу от всех установок вместе    | 10 в сутки                   |
| Писем от домена, первые 14 дней после ключа     | 100 в сутки                  |
| Писем от домена дальше                          | 500 в сутки                  |
| Писем на адреса, куда домен ещё не писал        | 50 / 300 в сутки             |
| Домен на платформе бесплатных поддоменов        | 30 в сутки, новых адресов 10 |
| Частота запросов домена                         | 60 в минуту                  |
| Регистраций с одного IP (IPv6 — с одной /64)    | 5 в час                      |
| Неподтверждённых регистраций адреса с одного IP | 5 в сутки                    |

**Почему 6 на пользователя.** Владелец задал 5–8. Обычный день человека в почте Coma —
одно-два письма: приглашение или подтверждение, иногда сброс пароля, один дайджест.
Тяжёлый, но честный день: приглашение пришло, ссылка ушла в спам, админ отправил
повторно (2), человек забыл пароль и запросил сброс дважды (4), сменил почту (5),
вечером пришёл дайджест (6). Шесть покрывают такой день без отказа. Семь-восемь
ничего не добавляют честному сценарию, но на треть увеличивают число писем, которые
недобросовестная установка может отправить одному чужому человеку. Пять режут
этот тяжёлый день на последнем письме.

Лимит на получателя считается по HMAC адреса (секрет сервиса), поэтому «пользователь
установки» для сервиса — это адрес, на который она пишет. Лимит установки фиксирован:
сервис не знает, сколько у установки людей, а доверять её словам нельзя. Оператор
меняет лимит конкретной установки командой `mail-relay set-limit`. 500 в сутки хватает
пространству примерно на 80 активных людей с дайджестами. Больше — свой SMTP.

Установка соблюдает лимиты и со своей стороны: дайджест через почту Coma уходит не
чаще раза в 12 часов, а при `429` письмо не повторяется до сброса окна.

### Приватность

- Сервис хранит HMAC адреса получателя, тип письма, время, id письма у RuSender и
  статус. Адрес открытым текстом и данные писем в базе сервиса не хранятся и не
  пишутся в журнал. Адрес и собранное письмо видит RuSender — как любой поставщик
  доставки.
- Дайджест через сервис содержит только счётчики (всего, упоминаний, личных,
  чатов) и ссылки на приложение. Текстов сообщений, имён чатов и авторов в нём нет.
  Через свой SMTP дайджест остаётся подробным, как раньше: письмо не покидает
  инфраструктуру владельца.
- Способ доставки виден в «Инфраструктуре» (веб и телефон): «Почта Coma», «Свой SMTP»
  или «Не отправлять». Переключение — в один шаг, без перезапуска.
- В политике обработки персональных данных Coma нужен раздел о почтовом сервисе:
  какие данные он видит, кому их передаёт (RuSender) и сколько хранит (журнал писем —
  30 дней, затем удаляется).

### Очередь и повторы в установке

Core пробует отправить сразу (10 секунд). Временный сбой (сеть, `5xx`, `429` с
`Retry-After`) кладёт письмо в `mail_outbox`: данные письма зашифрованы ключом
интеграций, повтор с экспоненциальной задержкой, тот же `Idempotency-Key`. Письмо со
ссылкой живёт в очереди не дольше срока ссылки. Исчерпанный лимит и отзыв ключа —
постоянные отказы: сброс пароля отменяет токен и сообщает об ошибке, приглашение
остаётся без письма (админ копирует ссылку), дайджест помечается пропущенным.

### Остаточные риски

- Хостинги, которых нет в Public Suffix List (`tilda.ws`, `ucoz.ru`, `narod.ru` и
  т. п.), считаются одним доменом: недобросовестный клиент хостинга тратит общий
  лимит и может вызвать общую приостановку. Разбирает оператор (`set-limit`,
  `restore`).
- Злоумышленник с собственными доменами получает по 100–500 писем в сутки на домен
  после проверки адреса. Сдерживают шаблоны, ссылки только на его же домен,
  домен ссылки в письме, жалобы и ручной `revoke`.
- Небольшую установку могут приостановить на 72 часа трое разных людей, которые
  получили от неё письма и нажали «Спам». Приостановка снимается сама.
- Вебхуки RuSender без подписи: защита — секрет в пути и выключенный журнал nginx.

## Последствия

- У проекта появляется второй production-сервис и расход на RuSender. Недоступность
  сервиса задерживает письма, сообщения и вход по паролю она не трогает.
- Компрометация сервиса раскрывает HMAC адресов и метаданные отправки. Токен RuSender
  даёт право отправлять письма от `coma-chat.com`, поэтому у него только право
  `email.send`, хранится он в файле вне git и ротируется в кабинете RuSender.
- Жалобы на письма установки бьют по репутации общего домена. Защита — шаблоны,
  ссылки только на свой адрес, лимиты и автоматическая приостановка.
- Установки без публичного HTTPS (локальная разработка, закрытые контуры) почтой
  Coma не пользуются.
