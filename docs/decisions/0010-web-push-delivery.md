# ADR-0010: надёжная доставка уведомлений

- Статус: принято
- Дата: 2026-08-19

## Контекст

Web Push является побочным каналом уведомления, а не частью durable WebSocket delivery. Отправка напрямую из HTTP handler или Redis Pub/Sub потеряется при рестарте и не даст контролировать повтор, настройки пользователя и недействительные browser subscriptions.

## Решение

`message.created`, `reaction.added` и адресные события состава чата в той же PostgreSQL-транзакции создают уникальную `notification_job` для durable event. Worker короткими батчами вычисляет получателей и материализует Web Push-доставки на актуальные subscriptions. Доставки атомарно забираются через `FOR UPDATE SKIP LOCKED` и ограниченный lease. Уникальность `(org_id, event_seq, subscription_id)` защищает материализацию от повторов, lease — от одновременной отправки двумя репликами и допускает восстановление после падения worker.

Перед материализацией проверяются membership, глобальный `push_enabled`, `notify_level`, mute и mentions. Непосредственно перед отправкой active-screen lease из realtime hub может подавить push открытого чата; Redis и lease остаются только оптимизацией и не влияют на сохранность события.

- успешный ответ провайдера завершает delivery;
- `404`/`410` удаляют недействительную subscription;
- временные ошибки повторяются с ограниченным exponential backoff;
- payload по умолчанию содержит автора, чат и deep link, но не текст сообщения;
- текст включается только настройкой `push_preview`;
- VAPID private key хранится только в server environment, public key доступен клиенту через capability endpoint.

Browser permission запрашивается только после явного действия пользователя. Service worker открывает существующее окно либо создаёт новое по deep link. Отказ или отсутствие Push API не блокируют мессенджер.

Email-дайджест является вторым потребителем той же вычисленной выборки получателей и не зависит от наличия VAPID или browser subscription. Для пользователя с включённым `email_digest` создаётся уникальный durable item на пару event/actor с задержкой 15 минут для пакетирования. Активность в соответствующем чате подавляет письмо окончательно; успешная SMTP-доставка завершает весь пакет, временная ошибка повторяется с bounded exponential backoff. Если SMTP отключён до отправки, пакет завершается как `smtp_unavailable`, чтобы старые уведомления не ушли неожиданно после будущей настройки почты. Privacy preview одинаков для Push и email.

## Последствия

Push и email-дайджест переживают рестарты Core и не дублируются при повторной материализации. PostgreSQL остаётся источником истины, а будущая замена транспорта очереди требует бенчмарка и не меняет клиентский контракт.
