### Хранилище файлов — сознательно не сделано в PR #20 (пакет D)

- [ ] Асинхронное завершение больших загрузок. Сейчас копирование на сервере
      идёт внутри запроса `complete`, отвязанное от клиента, с таймаутом 30 с +
      1 с на 20 МиБ (35 с для `FILE_MAX_BYTES` по умолчанию, 100 МиБ) и арендой
      захвата. При `FILE_MAX_BYTES` в гигабайты нужен фоновый job и статус
      «завершается» в API.
- [ ] Объекты файлов в статусе `deleted`, которые когда-то были готовы, сверка
      больше не удаляет (принцип «никогда не удалять объект бывшего готового
      файла»). Аватары и превью удаляют объект явно; если явное удаление не
      удалось, объект остаётся навсегда. Нужен отдельный явный и журналируемый
      путь удаления для таких объектов (с задержкой и проверкой хранилища).
- [ ] Очистка непривязанных файлов (`cleanupUnattached`, было до PR #20) удаляет
      объекты готовых файлов, не прикреплённых ни к сообщению, ни к аватару, ни
      к базе знаний, через `FILE_UPLOAD_TTL` (24 ч). Это намеренное поведение
      продукта, но единственный путь сверки, удаляющий объект бывшего готового
      файла — решить, оставлять ли.
- [ ] Защита от «не того хранилища» останавливает проход, когда не меньше 3
      впервые проверенных объектов отсутствуют и ни один из них не найден.
      Частично неверное хранилище (например, старая копия бакета) её не
      включит: отсутствующие в нём файлы станут `failed` через час (объекты не
      удаляются, файлы вернутся в `ready`, когда хранилище исправят).
- [ ] Перевод стейджинга с MinIO на versitygw — по решению владельца продукта,
      по процедуре из `docs/runbooks/files-search.md`; до этого стейджинг
      остаётся на MinIO без изменений. Резервное копирование тома шлюза.
- [ ] Клиент исчерпывает повторы `complete` (6 попыток, до 30 с паузы)
      раньше, чем истекает аренда завершения (35–60 с и больше для больших
      файлов): показывает ошибку, хотя сервер доведёт загрузку, и повторное
      открытие покажет готовый файл. Согласовать число повторов с арендой.
- [ ] Внешнее оповещение на остановку сверки (`ErrStorageSuspect`): сейчас
      только запись `file reconciliation failed` в логе Core.
- [ ] Номера миграций: C слит с `00051`, хранилище — `00052`, голосовые —
      `00053`; пакет G (`feat/6.1-saved-messages`) перенумерован в `00054`
