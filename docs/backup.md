# Резервные копии и восстановление Coma

Для установок из готовых образов ([docs/install.md](install.md)).

## Что входит в копию

`./backup.sh` собирает один архив `backups/coma-<дата>-<версия>.tar`, в котором лежат:

- `database.dump`: дамп PostgreSQL (`pg_dump -Fc`): пользователи, чаты, сообщения, настройки, сведения о файлах;
- `files.tar.gz`: файлы из тома Docker, если `STORAGE_DRIVER=local`. Для встроенного S3 вместо него `s3-data.tar.gz` и `s3-meta.tar.gz`;
- `env`: копия `.env` с паролем базы и `INTEGRATION_ENCRYPTION_KEY`. Без этого ключа пароли интеграций (SMTP, S3, ключи моделей) не расшифровать, их придётся вводить заново;
- `manifest.txt`: версия Coma, версия схемы базы, дата.

В копию не входят Redis (служебные данные, восстанавливаются сами) и сертификаты Caddy (выпускаются заново). Файлы во внешнем S3 в архив тоже не попадают: включите у провайдера версионирование или репликацию бакета.

В архиве вся переписка и ключи шифрования. Доступ к нему должен быть не шире, чем к самому серверу: права `0600`, отдельный бакет, пароль на архив.

## Настройка

```sh
cd /opt/coma
cp backup.env.example backup.env
```

| Переменная                                                                               | Значение                                                                       |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `BACKUP_DIR`                                                                             | куда класть архивы, по умолчанию `./backups`                                   |
| `BACKUP_KEEP`                                                                            | сколько последних архивов хранить, по умолчанию 14                             |
| `BACKUP_PASSPHRASE_FILE`                                                                 | файл с паролем: архив шифруется AES-256 (`openssl enc`), получается `.tar.enc` |
| `BACKUP_S3_URL`                                                                          | `s3://бакет/папка`: каждый архив выгружается туда                              |
| `BACKUP_S3_ENDPOINT`, `BACKUP_S3_REGION`, `BACKUP_S3_ACCESS_KEY`, `BACKUP_S3_SECRET_KEY` | доступ к хранилищу                                                             |
| `BACKUP_S3_KEEP`                                                                         | сколько архивов хранить в S3, по умолчанию как `BACKUP_KEEP`                   |

Файл с паролем храните ещё где-нибудь, кроме этого сервера, например в менеджере паролей. Если сервер сгорит вместе с файлом пароля, зашифрованную копию не открыть.

Расписание: каждую ночь в 03:15.

```sh
( crontab -l 2>/dev/null; echo '15 3 * * * cd /opt/coma && ./backup.sh >> backups/backup.log 2>&1' ) | crontab -
```

Пока делается копия, Coma работает. Сначала снимается дамп базы, потом архивируются файлы. Файл, загруженный между этими шагами, попадёт в архив без записи в базе. Это безопасно: Core сам убирает такие файлы.

## Восстановление

Восстановление полностью заменяет базу, файлы и ключи установки содержимым архива.

### На том же сервере

```sh
cd /opt/coma
./restore.sh backups/coma-20261117-031500-0.1.0.tar
```

Скрипт спросит подтверждение (`--yes` пропускает вопрос). Затем он:

1. сохраняет текущий `.env` как `.env.before-restore-<дата>` и ставит на его место `.env` из архива, оставляя `COMA_VERSION` текущей установки;
2. останавливает Coma, пересоздаёт базу и загружает дамп;
3. заменяет файлы в томе;
4. запускает Coma и ждёт, пока все сервисы станут `healthy`.

### На новом сервере

1. Поставьте Docker и скачайте файлы установки той же или более новой версии (шаги 2–3 из [install.md](install.md)). `generate-env.sh` запускать не нужно: ключи придут из архива.
2. Скопируйте архив на сервер, например в `/opt/coma/backups/`. Для `.tar.enc` положите рядом `backup.env` с `BACKUP_PASSPHRASE_FILE`.
3. `./restore.sh backups/coma-….tar`
4. Если у нового сервера другой адрес, поправьте в `.env` `COMA_SITE_ADDRESS` и `PUBLIC_APP_URL`, затем выполните `docker compose up -d --wait`.

Восстановить копию в более старую версию Coma не получится: Core откажется запускаться на более новой схеме базы ([upgrade.md](upgrade.md)).

## Проверка копии

Проверяйте копию раз в квартал и после изменений в установке, на отдельной машине или виртуалке. Проверка занимает около 15 минут:

1. Восстановите последний архив по шагам «На новом сервере». Если домен другой, хватит пробного адреса `localhost:8088`.
2. Войдите под своей учётной записью, откройте несколько чатов и скачайте пару файлов.
3. Удалите проверочную установку: `docker compose down -v`.

Тот же цикл (установка → сообщение с файлом → копия → восстановление в пустую установку → вход и проверка файла) автоматически проверяется для каждого изменения в репозитории и каждого выпуска: [`scripts/check-release-install.sh`](../scripts/check-release-install.sh).
