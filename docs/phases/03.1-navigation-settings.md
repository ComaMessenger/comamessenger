# Фаза 3.1. Навигация и настройки

Статус: в работе; навигация и базовый каркас settings routes готовы, расширенные серверные контракты ещё не реализованы.

## Почему это отдельная подфаза

Фаза 1 дала серверное редактирование собственного профиля, а фаза 3 — минимальный UI preferences. Полноценная информационная архитектура настроек пространства, безопасности и устройств в плане явно не была зафиксирована. Фаза 3.1 закрывает этот пробел до файлов и глобального поиска, не откладывая базовый Web UX до нативного клиента фазы 6.

## Навигация

- На phone-width глобальный sidebar заменяется фиксированным нижним tabbar: `Чаты`, `Треды`, `Важные`, `Участники`, `Ещё`.
- Tabbar остаётся доступен в списках, открытом чате, треде и разделе `Ещё`; учитывает safe area и экранную клавиатуру.
- `Ещё` — отдельный прокручиваемый route `/more`, а не popover. Он содержит профиль, пространство, уведомления и выход.
- Desktop sidebar остаётся постоянным. Все utility/settings routes заменяют только основную рабочую область.
- Активный tab определяется route, deep links не хранят navigation state отдельно.

## Настройки профиля

- Route `/settings/profile`, без modal/dialog composition.
- Имя, handle, timezone, язык, light/dark/system theme.
- Push permission, preview privacy и chat notification defaults.
- Список активных сессий, текущая сессия, отзыв отдельной сессии и выход со всех устройств.
- Аватар добавляется после file contract фазы 4; до этого используется стабильный initials avatar.

## Настройки пространства

- Route `/settings/workspace`, доступ и мутации проверяются сервером по organization role.
- Основное: название и slug с явными правилами изменения адреса.
- Участники: приглашения, роли, деактивация и политика самостоятельного вступления.
- Коммуникации: defaults для уведомлений, создания public chats/channels и публикации в каналах.
- Хранение: bundled MinIO или внешний S3-compatible provider, bucket/region/endpoint, проверка подключения без возврата secrets клиенту.
- Безопасность: session lifetime, invitation TTL и audit view; retention policy добавляется только вместе с durable deletion contract.

## Contract gate

До UI дополнительных полей нужно добавить и закоммитить OpenAPI для:

1. чтения/обновления organization settings с optimistic concurrency/version;
2. списка и отзыва user sessions, включая logout-all-except-current;
3. invitation defaults и member deactivation;
4. masked storage configuration + server-side connection test;
5. audit events для каждой административной мутации.

Secrets S3 никогда не возвращаются после записи. Скрытый control не заменяет authz; прямые API-вызовы покрываются integration tests.

## Definition of Done

- Settings не открываются в dialog на desktop или phone.
- Profile changes отражаются в sidebar/tab `Ещё` без перезагрузки.
- Member не может открыть или вызвать workspace mutations, разрешённые только owner/admin.
- Каждая настройка либо работает через committed API, либо отсутствует в production UI; декоративных disabled controls нет.
- Phone tabbar и settings routes проходят keyboard/screen-reader, safe-area и visual-regression проверки.
- RU/EN каталоги и pseudo-locale остаются синхронными.
