# Фаза 7.1 — почтовый сервис Coma

Статус: план и реализация, 2026-11-16. Решение и его причины —
[ADR-0013](../decisions/0013-mail-relay.md). Эксплуатация —
[`runbooks/mail-relay.md`](../runbooks/mail-relay.md).

## Цель

Новая установка Coma с публичным HTTPS-адресом отправляет приглашения, сброс пароля,
подтверждение почты и дайджест без настройки SMTP. Администратор видит в настройках,
что письма идут через почту Coma и сколько лимита осталось. Почту Coma можно
выключить или заменить своим SMTP.

## В scope

- Сервис `mail-relay`: регистрация установки, подтверждение её адреса, отправка
  письма по типу и данным, лимиты, вебхуки RuSender, отзыв ключа, команды оператора.
- Пакет `mailtemplate`: шаблоны писем на русском и английском, общие для сервиса и для
  отправки через свой SMTP.
- Core: способ доставки пространства, клиент сервиса, очередь повторов, эндпоинт
  проверки адреса, учёт лимита для дайджеста.
- Веб и телефон: раздел «Почта» в «Инфраструктуре» — способ доставки, состояние
  почты Coma, счётчик лимита, поля SMTP только для «Своего SMTP».
- Документы: ADR, этот план, runbook, переменные в `.env.example`.

## Вне scope

- Развёртывание на сервер (делает основной сеанс по runbook).
- Платные тарифы и увеличение лимита по запросу (пока — команда оператора).
- Письма с вложениями, произвольные письма от агентов и интеграций.
- Отписка от дайджеста через ссылку RuSender: она заблокировала бы получателю все
  письма ключа, включая сброс пароля. Ссылка в дайджесте ведёт в настройки
  уведомлений Coma.

## Пользовательские сценарии

1. Админ новой установки приглашает коллегу по почте — коллега получает письмо
   «Анна приглашает вас в «Ромашку»» от «Ромашка через Coma <no-reply@coma-chat.com>».
2. Сотрудник забыл пароль — приходит письмо со ссылкой на час.
3. Админ открывает «Инфраструктура → Почта» и видит «Почта Coma · подключена ·
   за сутки 14 из 100 писем».
4. Админ хочет письма от своего домена — выбирает «Свой SMTP», вводит сервер.
5. Админ закрытого контура выбирает «Не отправлять» — письма не уходят никуда.

## Контракт установка ↔ сервис

Базовый адрес — `MAIL_RELAY_URL` (по умолчанию `https://mail.coma-chat.com`). Все
ответы — JSON, ошибки — `{"error": "<код>", "message": "…"}`.

| Запрос                           | Тело и ответ                                                                                    |
| -------------------------------- | ----------------------------------------------------------------------------------------------- |
| `POST /v1/installations`         | `{app_url}` → `201 {installation_id, key, challenge, status: "pending"}`; `429` по IP.          |
| `POST /v1/installations/verify`  | Bearer-ключ → сервис читает `{app_url}/api/v1/mail-relay/challenge` → `200 {status: "active"}`. |
| `GET /v1/quota`                  | Bearer-ключ → `200 {status, daily_limit, used, per_recipient_limit, window_hours}`.             |
| `POST /v1/messages`              | Bearer-ключ, `Idempotency-Key` → `202 {id, status: "queued"}`.                                  |
| `POST /v1/webhooks/rusender/{s}` | События RuSender → `204`.                                                                       |
| `GET /healthz`                   | `204`.                                                                                          |

Ответ установки на проверку адреса:
`GET /api/v1/mail-relay/challenge` → `200 {"installation_id": "…", "challenge": "…"}`, без
авторизации; пока регистрации нет — `404`.

Тело `POST /v1/messages`:

```json
{
  "type": "invitation",
  "to": "anna@example.com",
  "locale": "ru",
  "workspace_name": "Ромашка",
  "data": {
    "link": "https://chat.romashka.ru/invite/…",
    "inviter_name": "Иван Петров",
    "role": "member",
    "expires_at": "2026-11-23T10:00:00Z"
  }
}
```

| `type`                | `data`                                                                  |
| --------------------- | ----------------------------------------------------------------------- |
| `invitation`          | `link`, `inviter_name?`, `role` (`member`/`admin`), `expires_at`        |
| `password_reset`      | `link`                                                                  |
| `email_confirmation`  | `link`                                                                  |
| `email_change_notice` | — (письмо старому адресу: «почту меняют»; без ссылок)                   |
| `digest`              | `link`, `settings_link`, `total`, `mentions`, `direct`, `chats` (числа) |

Неизвестные поля — `400`. `locale` — `ru` или `en`, иначе `ru`.

Коды ошибок `POST /v1/messages`:

| HTTP    | `error`                                  | Что делает установка                                            |
| ------- | ---------------------------------------- | --------------------------------------------------------------- |
| 400     | `invalid_request`, `invalid_link`        | Постоянный отказ, ошибка в журнал.                              |
| 401     | `invalid_key`                            | Сбросить регистрацию, зарегистрироваться заново.                |
| 403     | `installation_pending`                   | Повторить проверку адреса.                                      |
| 403     | `installation_replaced`                  | Зарегистрироваться заново: адрес переустановлен.                |
| 403     | `installation_revoked`                   | Показать в настройках, предложить свой SMTP.                    |
| 409     | `idempotency_conflict`                   | Постоянный отказ (тот же ключ, другие данные).                  |
| 422     | `recipient_suppressed`                   | Постоянный отказ: адрес жаловался, отписался или не существует. |
| 429     | `recipient_limit`, `installation_limit`  | Постоянный отказ до конца окна.                                 |
| 429     | `rate_limited` (+ `Retry-After`)         | Повтор из очереди.                                              |
| 502/503 | `provider_unavailable`, `provider_quota` | Повтор из очереди.                                              |

Повтор с тем же `Idempotency-Key` и теми же данными возвращает прежний ответ и не
тратит лимит.

## Сервис

- `core/cmd/mail-relay`: `serve` (по умолчанию), `installations`, `revoke <id> <причина>`,
  `restore <id>`, `set-limit <id> <писем в сутки>`.
- `core/internal/mailrelay`: HTTP API, хранилище (схема создаётся при старте, как у
  push-relay), клиент RuSender, проверка адреса через `netguard`, вебхуки.
- Таблицы: `mail_installations` (id, sha256 ключа, app_url, challenge, status, лимит,
  счётчики жалоб), `mail_sends` (id, установка, тип, HMAC адреса, idempotency key,
  отпечаток данных, id письма RuSender, статус, время), `mail_suppressions` (HMAC
  адреса, причина, время).
- Журнал писем хранится 30 дней, раз в час старые строки удаляются.

## Изменения в core

- Миграция `00064_mail_relay.sql`: `mail_relay_state` (одна строка: адрес сервиса,
  installation_id, ключ в шифре, challenge, статус, последняя ошибка), `mail_outbox`
  (зашифрованное письмо, попытки, срок, ошибка).
- `config`: `MAIL_RELAY_URL` (`off` выключает), проверка `https`.
- `mailtemplate`: типы писем и сборка темы, текста и HTML.
- `mailer`: выбор транспорта по способу доставки пространства, клиент сервиса,
  регистрация и проверка адреса в фоне, очередь повторов, кэш квоты на минуту.
- `identity`, `push`: вместо «тема + текст» передают типизированное письмо.
- Способ доставки (`mail_delivery`: `coma`, `smtp`, `off`) хранится в настройках
  интеграций. Для существующих пространств с заполненным SMTP по умолчанию — `smtp`,
  для остальных — `coma`.
- `GET /organization/infrastructure` отдаёт `mail`: способ, состояние почты Coma
  (`unavailable`, `registering`, `active`, `revoked`, `error`), `used`, `daily_limit`,
  `per_recipient_limit`.
- Дайджест через почту Coma — только счётчики и не чаще раза в 12 часов на человека.

## Настройки в вебе и телефоне

Раздел «Почта» в «Инфраструктуре»:

- три варианта: «Почта Coma», «Свой SMTP», «Не отправлять»;
- для «Почты Coma» — состояние и счётчик «за сутки N из M писем, одному человеку — не
  больше 6», пояснение про дайджест без текстов сообщений;
- поля SMTP и «Проверить подключение» — только для «Своего SMTP».

## DNS и кабинет RuSender

Проверено через DoH Cloudflare 2026-11-16 (локальный `dig` в среде разработки
перехватывается прокси и возвращает адреса `198.18.x.x`; сверять только через внешний
резолвер или DoH):

| Запись                              | Значение                                                                          | Итог                  |
| ----------------------------------- | --------------------------------------------------------------------------------- | --------------------- |
| `coma-chat.com TXT` (SPF)           | `v=spf1 include:rsndr.ru a mx include:_spf.hosting.reg.ru ip4:31.31.197.100 ~all` | есть RuSender         |
| `mdmdmail._domainkey.coma-chat.com` | `v=DKIM1;k=rsa;p=MIIB…` (2048 бит)                                                | есть                  |
| `_dmarc.coma-chat.com`              | `v=DMARC1; p=none; rua=mailto:postmaster@mx1.rusender-mail.ru`                    | есть, мягкая политика |
| `coma-chat.com MX`                  | `mx1/mx2.hosting.reg.ru`                                                          | есть                  |
| `mail.coma-chat.com A`              | —                                                                                 | **нет**               |

Что нужно владельцу:

1. A-запись `mail.coma-chat.com` → IP сервера (тот же, что у `push.coma-chat.com`) и
   сертификат при выкатке.
2. Через 2–4 недели без проблем ужесточить DMARC до `p=quarantine`; отчёты `rua` сейчас
   уходят RuSender — добавить свой адрес, если нужна сводка.
3. В кабинете RuSender: вебхук «Транзакционные письма — подробные» на
   `https://mail.coma-chat.com/v1/webhooks/rusender/<секрет>`; проверить тариф (бесплатно
   100 писем в месяц — хватит только на бету).
4. Токен с правом только `email.send` — уже так: на чтение доменов и ключей API
   отвечает `SCOPE_REQUIRED`.

## Критерии приёмки

- Дано установка с публичным HTTPS-адресом и почтой Coma; когда админ приглашает
  коллегу, тогда коллега получает письмо по шаблону от «X через Coma».
- Дано установка отправила одному адресу 6 писем за сутки; когда она шлёт седьмое,
  тогда сервис отвечает `429 recipient_limit`, а RuSender запроса не получает.
- Дано ссылка в данных ведёт не на адрес установки; тогда `400 invalid_link`.
- Дано в имени пространства адрес сайта; тогда в письме нейтральное имя.
- Дано 3 жалобы за 7 дней; тогда ключ приостановлен и установка видит «Почта Coma
  отключена».
- Дано админ выбрал «Не отправлять»; тогда письма не уходят, а сброс пароля по почте
  недоступен.

## Проверка качества

- Go-тесты сервиса с подменённым RuSender (`httptest`): контракт, лимиты, гонка,
  идемпотентность, ссылки, санитизация, вебхуки, отзыв.
- Go-тесты core: выбор транспорта, очередь, проверка адреса, дайджест без текста.
- vitest: модель настроек в `packages/core`, экраны веба и телефона; `tsc` телефона.
- Живая проверка: одно письмо-приглашение через RuSender на адрес владельца.
- Независимое ревью безопасности сервиса.

## Риски и открытые вопросы

- Месячная квота RuSender на бесплатном тарифе — 100 писем: на бету с несколькими
  установками не хватит. Нужен платный тариф до публичного выпуска.
- Вебхуки RuSender без подписи: секрет в пути — единственная защита; при утечке
  секрета его меняют.
- Лимит установки фиксирован; когда появятся тарифы, лимит станет частью тарифа.
