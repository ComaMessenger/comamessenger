# Детализация фаз

Общий roadmap хранится в [`../product-spec.md`](../product-spec.md). Перед началом фазы для неё создаётся отдельный файл `NN-short-name.md`.

## Шаблон фазы

```md
# Фаза N. Название

## Цель
Какое проверяемое состояние продукта должно быть достигнуто.

## В scope
- Что точно делаем.

## Вне scope
- Что сознательно откладываем.

## Пользовательские сценарии
- Какую законченную работу сможет выполнить пользователь.

## Технические задачи
- Задача, ожидаемый результат и зависимости.

## Контракты и данные
- Изменения API, событий, схемы БД и конфигурации.

## Критерии приёмки
- Проверяемое условие в формате «дано / когда / тогда».

## Проверка качества
- Автотесты, ручные сценарии, нагрузочные и security-проверки.

## Риски и открытые вопросы
- Решения, которые нужно принять до или во время фазы.

## Definition of Done
- Условия, при которых фазу можно закрыть.
```

## Зависимости и результат

| Фаза | Зависит от | Проверяемый результат |
|---|---|---|
| 0 | — | Проект собирается, запускается и проверяется в CI |
| 1 | 0 | Пользователи входят и управляют чатами/каналами через API |
| 2 | 1 | Два API-клиента надёжно обмениваются сообщениями в realtime |
| 3 | стабильные контракты 1–2 | Команда пользуется основным мессенджером через web |
| 4 | 2–3 | Файлы хранятся в S3-compatible storage и доступны в поиске |
| 5 | 2 и 4 | Встроенные и внешние агенты безопасно работают через публичный API |
| 6 | стабильные 2–5 | Рабочие iOS/Android internal builds с offline и push |
| 7 | 0–6 | Проверены install, upgrade, backup, restore и пилотная эксплуатация |
| 8 | 7 | Опубликован воспроизводимый и сопровождаемый v1.0 |

Фаза 3 может идти параллельно с завершением фазы 2 после заморозки конкретного набора API/WS-контрактов. Остальные параллельные работы допустимы только там, где их входные контракты уже зафиксированы.
