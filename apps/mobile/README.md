# Coma mobile

iPhone and Android phone client on Expo. Stack and constraints: [ADR-0011](../../docs/decisions/0011-mobile-stack.md); phase plan: [06-mobile.md](../../docs/phases/06-mobile.md).

`ios/` and `android/` are generated by `expo prebuild` and are not committed; native settings live in `app.config.ts` and config plugins.

## Development

The app uses native modules outside Expo Go, so run it in a development build:

```sh
pnpm --filter @comamessenger/mobile ios       # Xcode + iOS Simulator
pnpm --filter @comamessenger/mobile android   # Android Studio emulator
pnpm --filter @comamessenger/mobile start     # Metro for an installed development build
```

Cloud builds and signing go through EAS (`npx eas-cli@latest build --profile development`). Link the project once with `npx eas-cli@latest init`; credentials stay in EAS, never in the repository.

A local Core is reachable at `http://localhost:8080` from the iOS Simulator and at `http://10.0.2.2:8080` from the Android emulator. Plain HTTP is accepted only for these development hosts.

## Configuration

| Variable         | Purpose                                                                                      |
| ---------------- | -------------------------------------------------------------------------------------------- |
| `COMA_BUNDLE_ID` | iOS bundle identifier and Android package. Fixed before the first store build; see ADR-0011. |
